# NDS ARM9 反汇编 + TS移植全套辅助工具
分为5大类：ROM解包、反汇编/逆向分析、调试抓真值快照、辅助翻译、TS运行验证工具。贴合你前面那套「汇编语义移植TS、拒绝自创逻辑」的工作流。

## 一、ROM解包工具（提取素材+ARM9二进制）
> 目的：拿出ARM9.bin，导出Tile/Map/Pal/音频原始资源，移植直接复用素材
1. **ndstool**（命令行，首选）
    - 输出：`arm9.bin`、`arm7.bin`、全部资源、文件系统
    ```bash
    ndstool -x game.nds -9 arm9.bin -7 arm7.bin
    ```
2. **DSDecmp**
    - NDS压缩工具，很多ROM的ARM9、素材是LZ77压缩，必须先解压才能丢进反汇编器。
3. **Tinke**（GUI）
    - 可视化浏览NDS资源，预览贴图、瓦片、调色板，导出二进制tile/map/pal，适合快速校验导出素材完整性。
4. **NDS Resource Manager**
    - 资源批量导出，处理NCGR/NCLR/NMAP格式。

> 注意：移植不要导出图片PNG，**导出原始二进制NCGR/NCLR/NMAP**，TS内部解析硬件格式，避免二次转换带来色差、瓦片错位。

## 二、ARM9反汇编/逆向主工具（获取汇编、函数、结构体、内存地址）
### 1. Ghidra + Ghidra‑NDS插件【强烈推荐，免费】
- 插件：`ghidra‑nds`，直接加载`arm9.bin`，配置NDS内存映射（EWRAM/IWRAM/VRAM/MMIO）。
- 能力：自动函数识别、交叉引用、生成反汇编、导出完整反汇编文本、解析结构体，可导出C伪代码（**仅作参考，不能直接用，真值以汇编为准**）。
- 输出产物：可复制整段函数汇编文本，直接喂给你的AI提示词做TS翻译。
> 关键设置：手动配置NDS内存布局，设置MMIO地址，否则跳转、内存寻址全部错乱。

### 2. IDA Pro + NDS loader（商业）
- 成熟NDS加载器，对ARM9 THUMB指令识别最好。
- 可以导出汇编清单、生成`.asm`文件，断点调试配合模拟器调试器。
- 缺点：付费；优势交叉引用、栈布局分析强。

### 3. objdump（GNU binutils）
```bash
arm‑none‑eabi‑objdump -D -b binary -m armv5te arm9.bin > arm9_disasm.txt
```
- 快速批量导出完整原始反汇编文本。
- 缺点：**不会识别函数边界**，全部原始裸汇编，需要人工分割函数，适合作为原始素材给AI。

> ⚠️重要提醒：Ghidra/IDA生成的伪C代码是AI“猜测重构”，**不能当作真值**。真值永远是ARM汇编指令。

## 三、模拟器调试工具：抓“真值”（内存快照、寄存器dump，用来TS等价验证）
> 你的提示词强制每函数做等价验证，必须拿到**原始运行状态快照**，这一步是保证移植不跑偏的核心。
1. **DeSmuME 0.9.13‑debug版本（调试版，不要release）**
    - 核心能力：断点、查看R0‑R15、CPSR标志位、内存查看、内存dump保存bin文件，OAM/VRAM实时查看。
    - 使用流程：在目标函数入口下断点 → 保存寄存器快照 → dump一段内存 → 运行单步 → 再次dump内存、记录寄存器结果，作为AI的【等价验证】输入输出样例。
    - 导出：内存保存为`.bin`，TS单元测试直接加载做字节对比。
2. **melonDS（优先，精度高于DeSmuME）**
    - ARM调试器，支持THUMB单步，内存读写监视（watchpoint），MMIO跟踪。
    - 可以导出完整内存快照，适合做移植后回归对比。
    - 缺点：GUI调试界面不如DeSmuME直观。

> 工作流：melonDS跑原版ROM，断点截取「输入状态+输出状态」，直接粘贴到AI提示词的等价验证块。

## 四、辅助汇编→TS翻译工具（不是自动翻译，是辅助，不能替代人工+AI）
1. **ARM‑instruction‑reference手册**
    ARMv5TE指令集参考，确认每一条指令的CPSR标志更新规则（LDR、ADD、SUBS移位、带进位运算）。很多坑来自AI搞错ARM标志位更新逻辑。
2. **arm‑ts‑emulator 开源参考片段**
    Github上小型ARM解释器实现，参考：`updateFlags`进位溢出逻辑，直接抄进你的`NdsHardware`基座，避免自己写错ARM标志位。
> 禁止直接拿完整模拟器，你做的是**语义移植，不是写模拟器**，只复用标志位运算逻辑。

3. **TypedArray工具库（TS侧）**
    - `buffer‑io`：二进制读写辅助，加载ROM导出tile/pal二进制，u8/u16/u32大端小端转换（NDS是小端）。
    - 注意NDS ARM是小端序，TS读二进制务必处理`DataView`小端模式。

## 五、TS验证 & 单元测试工具（校验移植后的行为等价）
1. **Jest + ts‑node**
    - 写单元测试：把melonDS/DeSmuME导出的内存bin快照加载进`NdsHardware`实例，运行翻译后的TS函数，对比运行后内存每一字节、寄存器是否和模拟器快照完全一致。
    - 就是实现提示词中的「等价验证块」自动化，不要肉眼对比。
2. **pngjs / pixelmatch**
    - 加载原版渲染输出截图，对比TS渲染输出像素，校验2D硬件渲染逻辑移植正确性。
3. **Offset calculator小工具**
    快速计算结构体内存偏移，核对Ghidra结构体和TS interface偏移是否完全一致。

# 完整实操流水线（配合你之前的AI提示词）
1. ndstool解包ROM，解压arm9.bin，导出原始资源二进制。
2. Ghidra‑NDS加载arm9.bin，配置NDS内存映射，分析函数，复制目标函数汇编。
3. melonDS/DeSmuME调试版，在该函数断点，抓取【输入寄存器+内存快照】，单步执行抓取【输出寄存器+内存快照】。
4. 将：汇编文本 + MMIO表 + 快照输入输出，全部粘贴给AI，使用完整提示词，输出TS代码+等价验证块。
5. 将AI输出TS放入Jest单元测试，加载dump快照运行，逐字节对比内存/寄存器。
6. 不匹配 → 回查汇编，修正TS；匹配则进入下一个函数。

# 常见坑提醒
1. THUMB模式！NDS绝大部分代码运行在THUMB指令集，很多反汇编工具误识别成ARM，全部逻辑出错。Ghidra/IDA务必标记段为THUMB。
2. SUBS/ADDS才更新CPSR，ADD/SUB**不更新标志位**，这是移植最高发错误。
3. NDS小端序，TS DataView读写必须使用little‑endian。
4. Ghidra伪C经常做优化、合并分支，绝对不能当作真值，只参考。
