# MAP 模式（迷宫）反汇编实现分析报告

> 数据来源：`disasm/arm9-full.dis.txt`。所有结论带行号可回溯。
> 本报告回答：**迷宫模式（mode 0）在原版里到底怎么实现的？当前 TS 实现（`maze-scene.ts`）与真实行为差在哪？怎么修？**

---

## 1. 一句话结论

原版 map 模式游玩 = `GAME SETUP(0x2055F80)` 主循环 → 每帧返回 0 时按 mode 分派 → **mode 0 进入 `0x2059388`（迷宫游玩主函数，L68514-69504）**。

真实交互是：**下屏 5 个预置"槽位/位置"（方向键 LR 切换选中）+ 3 个触摸热区按钮**，触摸区域命中后翻转全局状态字节的位字段（bit0/bit1-2/bit3-4/bit5-6）驱动 UI，**不是"手指点击任意格子自由走"**。当前 `maze-scene.ts` 的"点击相邻白格移动"实现与原版机制不同。

---

## 2. 调用链（谁调谁）

```
主调度器 0x205113C (STATE 0x13 ST_GAMING)
  └─ 0x2055F80  GAME SETUP（游玩装配，3 refs: 0x202F014/0x202F0C8/0x202F180）
       └─ 主循环 L65400 (0x02056200)：
            每帧: 0x20563C8 主更新 → 返回 r4
            r4==0 → 按 mode 分派:
                     mode 0 → 0x2059388   ← 迷宫游玩（本报告主体）
                     mode 1 → 0x205A528   （lap）
                     mode 2 → 0x205B4F8   （fap）
            r4==1 → 0x2057210
            r4==2 → 0x20586C0
            r4==3 → 0x20568D8（完成检查；返回 0 → 结束游玩 0x20562E0）
            r4==4 → 0x205CEA0
            r4==5 → 清理退出
```

### 汇编：GAME SETUP 主循环与 mode 分派（L65400-65460）
```
0x02056200  mov      r0, r6            ; r6 = 游玩对象
0x02056204  mov      r1, r8
0x02056208  bl       #0x2028018        ; ← 读按键
0x0205620C  mov      r0, r6
0x02056210  mov      r1, r4            ; r4 = 上轮返回状态
0x02056214  bl       #0x20563c8        ; ← 主更新，返回 r4
0x02056218  movs     r4, r0
0x0205621C  bne      #0x2056268        ; r4 != 0 → 完成/结果分支
0x02056220  cmp      r5, #0            ; mode == 0 ?
0x02056224  bne      #0x2056238
0x02056228  mov      r0, r6
0x0205622C  mov      r1, r7            ; r7 = -1
0x02056230  bl       #0x2059388        ; ★ MAP 迷宫游玩每帧
0x02056234  b        #0x2056200        ; 回到主循环
; ---- r4 非 0 分支 ----
0x02056268  cmp      r4, #1
0x02056270  bl       #0x2057210        ; r4==1
0x02056280  cmp      r4, #2
0x02056288  bl       #0x20586c0        ; r4==2
0x02056298  cmp      r4, #3
0x020562A0  bl       #0x20568d8        ; r4==3 完成检查
0x020562AC  cmp      r0, #0
0x020562B0  beq      #0x20562e0        ; 返回 0 → 结束
0x020562B8  cmp      r4, #4
0x020562C0  bl       #0x205cea0        ; r4==4
0x020562D8  cmp      r4, #5
0x020562DC  bne      #0x2056200
0x020562E0  ... 清理对象 / 返回        ; r4==5 或完成 → 退出
```

> **结论**：迷宫游玩发生在 `0x2059388`，它在 GAME SETUP 主循环里**每帧被调用**（不阻塞），状态机由 `0x20563C8` 维护。

## 3. 迷宫游玩主函数 `0x2059388`（L68514-69504，约 990 行）

### 3.1 函数骨架
```
0x02059388  push {r4..fp, lr}
0x0205938C  sub  sp, sp, #0x8c
0x02059390  ldr  r4, [pc, #0xf64]          ; 常量表基址
0x02059394  add  r3, sp, #0x30             ; 栈区 buf[10B]（5×2 坐标对）
0x020593A0  mov  r2, #5
; ★ 复制 5 组 (x,y) 字节到 sp+0x30（5 个预置槽位坐标）
0x020593A4  ldrb r1, [r4]                  ; x
0x020593A8  ldrb r0, [r4, #1]              ; y
0x020593AC  add  r4, r4, #2
0x020593B0  strb r1, [r3]
0x020593B4  strb r0, [r3, #1]
0x020593B8  add  r3, r3, #2
0x020593BC  subs r2, r2, #1
0x020593C0  bne  #0x20593a4
0x020593C4  ldr  r0, [sp, #4]
0x020593C8  mov  r1, #1
0x020593CC  bl   #0x2028018                ; 读按键
; ---- 加载本关 LZ 数据 (type=9) ----
0x020593F0  mla  r2, r1, #0x18, r2         ; 关卡表寻址（每关 0x18 字节）
0x020593FC  bl   #0x20226b4                ; NiFi 加载
0x02059400  bl   #0x20591a0                ; VRAM/对象初始化
; ---- 创建 6 + 4 + 4 + ... 个 UI 对象（0x20223f0 创建 / 0x201fe64 设属性）----
; ...（L59414-59798 大量 0x20223f0 + 0x201fe64，属性码 0x5b/0x66/4/0x84/0x4b/7）
```

### 3.2 关键：5 个预置槽位坐标（L68518-68529）
```cpp
// 常量表（ARM9 偏移 0x81258 附近）5 组坐标
slot[0] = {x0, y0}; slot[1] = {x1, y1}; ... slot[4] = {x4, y4};
```
这些坐标稍后用于把当前选中对象移动到对应位置（L69248-69258）：
```
0x02059EFC  add  r3, sp, #0x30
0x02059F00  add  r3, r3, r8, lsl #1        ; 槽位 r8 × 2
0x02059F04  add  r2, sp, #0x30
0x02059F08  ldrb r3, [r3, #1]              ; y
0x02059F0C  ldrb r2, [r2, r8, lsl #1]      ; x
0x02059F10  mov  r0, sl                    ; 目标对象
0x02059F14  add  r3, r3, #0x200
0x02059F18  mov  r1, #4
0x02059F1C  lsl  r2, r2, #0xc              ; x << 12
0x02059F20  lsl  r3, r3, #0xc              ; (y+0x200) << 12
0x02059F24  bl   #0x201fe64                ; 设置对象位置
```
> 即：**选中槽位 sb → 把选中游标对象移到 `slot[sb]`**。

### 3.3 主输入循环（L68980-69110）
```
0x02059ACC  mvn  r0, #1
0x02059AD0  str  r0, [sp, #0x2c]           ; 触摸状态 = -2（未按下）
0x02059AD4  ldr  r0, [sp, #4]
0x02059AD8  mov  r1, #1
0x02059ADC  bl   #0x2028018                ; 读按键
0x02059AE0  ldr  r0, [sp, #0x2c]
0x02059AE8  add  r8, r0, #1                ; r8 = -1（当前选中槽位初值）
0x02059AF4  ldrh r0, [r0, #2]              ; 键状态
0x02059AF8  tst  r0, r1
0x02059AFC  beq  #0x2059b30                ; ─┐ 按键分支
; ── 左方向（L69033-69043）──
0x02059BA0  tst  r0, r1
0x02059BAC  beq  #0x2059bcc
0x02059BB0  cmp  sb, #0
0x02059BB8  moveq sb, #5                   ; 0 → 5（循环）
0x02059BBC  subne sb, sb, #1               ; sb-1
0x02059BC0  mov  r8, sb
; ── 右方向（L69044-69054）──
0x02059BCC  tst  r0, r1
0x02059BD8  beq  #0x2059bf8
0x02059BDC  cmp  sb, #5
0x02059BE4  moveq sb, #0                   ; 5 → 0（循环）
0x02059BE8  addne sb, sb, #1               ; sb+1
0x02059BF0  mov  r8, sb
; ── A 键 / 触摸确认（L69055-69112）──
0x02059BF8  tst  r0, r3
0x02059C18  cmp  sb, #4
0x02059C1C  bne  #0x2059ce0
;   ★ 修改全局状态字节 bit5-6（计数器 0..2）
0x02059C20  ldr  r0, [r5, #4]
0x02059C28  lsl  r2, r1, #0x1a
0x02059C2C  lsr  r3, r2, #0x1e             ; state = (b >> 5) & 3
0x02059C30  cmp  r3, #2
0x02059C34  bhs  #0x2059ce0
0x02059C38  bic  r2, r1, #0x30
0x02059C3C  add  r1, r3, #1
0x02059C4C  strb r1, [r0]                  ; state+1
```

### 3.4 触摸热区判定（L69113-69153）
```
0x02059CE0  cmp  r8, #0
0x02059CE4  bge  #0x2059e58
0x02059CE8  mov  r0, #6
0x02059CF0  bl   #0x202ead4                ; 读触摸 → r8 = 触摸槽位
0x02059CF8  cmp  sb, #4
0x02059CFC  cmpeq r8, sb
0x02059D00  bne  #0x2059e58
; ★ 触摸坐标 [r4] X / [r4,#2] Y（16bit）
0x02059D1C  ldrh r1, [r4]                  ; X
0x02059D20  cmp  r1, #0x7a                 ; 热区1 X∈[0x7a,0x8a)
0x02059D28  cmp  r1, #0x8a
0x02059D30  ldrh r0, [r4, #2]              ; Y
0x02059D34  cmp  r0, #0x86                 ; Y∈[0x86,0x96)
0x02059D40  cmp  r0, #0x96
;   → 命中热区1：清状态字节 bit5-6（state→0）+ 播放音效
0x02059D44  ldr  r2, [r5, #4]
0x02059D48  ldrb r0, [r2]
0x02059D54  beq  #0x2059e58
0x02059D58  bic  r0, r0, #0x30
0x02059D5C  strb r0, [r2]
0x02059D64  bl   #0x2027c34                ; 音效
; 热区2 X∈[0xa2,0xb2) 同构（L69154-69180）
; 热区3 X∈[0xca,0xda) 同构（L69181-69206）
```
> 三个触摸热区：`X[0x7a,0x8a)/[0xa2,0xb2)/[0xca,0xda)` × `Y[0x86,0x96)`。命中即翻转全局字节对应位段（bit5-6 / bit1-2 / bit0），并触发音效（`0x2027e10`）。

### 3.5 UI 状态位 → 显隐切换（L69207-69484）
- `[r5,#4]` 全局状态字节：`bit0`=开关、`bit1-2`=模式 0-3、`bit3-4`=模式 0-3、`bit5-6`=计数 0-3
- 每帧根据位值 `0x201fe64` 批量设置 6+4 组对象的显隐/位置（sp+0x3c~0x64 存对象句柄）
- `r8==5`（槽位 5）→ 退出流程（L69339-69351 → 0x205A2B0 清理）

### 3.6 触摸读取 `0x202EAD4`（L34386-34404）
```
0x0202EAD4  bl   0x2027930      ; 取触摸命中对象
0x0202EADC  cmp  r0, #0
0x0202EAE0  blt  返回 -1
0x0202EAF0  ldr  r2, [r1, #4]   ; 上次槽位
0x0202EAF4  cmp  r0, r2
0x0202EAF8  bne  记录新槽位
0x0202EAFC  ldr  r0, [r1, #0xc] ; 按下计数
0x0202EB00  add  r0, r0, #1
0x0202EB08  cmp  r0, #0x3c      ; 60 帧长按 → 重复触发
0x0202EB0C  ble  返回
0x0202EB10  mov  r0, r2         ; 返回当前槽位
```
> 触摸按下 60 帧（1 秒）内只触发一次，超过后每帧重复 —— 防连点。

## 4. 原版与当前 TS 实现的差异（BUG 分析）

| 维度 | 原版（反汇编证据） | 当前 `maze-scene.ts` | 结论 |
|------|-------------------|----------------------|------|
| 输入方式 | 方向键 LR 切换 5 槽位 + 3 个触摸热区按钮 | 任意触摸相邻白格 | **不一致**：原版不是"自由点格" |
| 移动目标 | 5 个**预置槽位坐标**（L68518-68529 常量表） | 全迷宫任意白格 | **不一致**：原版只有 5 个可选中位置 |
| 状态模型 | 全局字节位字段（bit0/1-2/3-4/5-6）+ 音效 | visited 数组 + 百分比 | 机制不同 |
| 完成判定 | 0x20568D8 完成检查（r4==3 分支） | visitedCount ≥ totalPath | 需对齐 |
| 触发放置 | 点击热区 1/2/3 翻转位段 | mark() 标绿 | 需对齐 |

**当前实现本质**：`maze-scene.ts` 的"点击相邻白格移动 + 上屏 palette 填充"是**从截图推断**的玩法（BUG-010 修复产物），并非来自反汇编。反汇编显示原版是**"5 槽位选择 + 3 热区按钮"的驱动模型**。

## 5. 修复建议（按优先级）

### 5.1 数据/机制对齐（必须先做）
1. **定位 5 槽位坐标常量表**：`0x2059388` 开头复制 5 组坐标的源地址 = `L68517` `[pc,#0xf64]`，即 ARM9 偏移 `0x0x2059388+8+0xf64 → 0x0205A2F4`（需从该处读 4 字节指针再定位）。把 5 组 (x,y) 提取出来，作为下屏 5 个可选中槽位坐标。
2. **还原全局状态字节语义**：`[r5,#4]` 指向的全局结构（猜测 `0x020DEB70` 系）的 bit 字段，需对照 `0x20563C8`（主更新，同样操作该字节）确认 bit0=开关、bit1-2=模式、bit5-6=计数的用途。
3. **触摸热区坐标写死**：`X[0x7a,0x8a)/[0xa2,0xb2)/[0xca,0xda)` × `Y[0x86,0x96)` 是下屏 3 个按钮热区，直接映射到 TS `onTouch` 的命中检测。

### 5.2 场景重写方向
- `MazeScene` 改为：**5 槽位高亮 + LR/触摸切槽位 + 3 热区按钮**，选中槽位才可放置/移动，放置判定不再依赖"四邻域"。
- 上屏填充逻辑保留（palette 填充方向正确），但触发源改为"槽位放置"。
- 完成判定改由 `engine.checkCompleteResult()` 统一（对齐 0x20568D8），而不是场景内自算百分比。

### 5.3 需要进一步逆向的点（当前仍未知）
- 5 组槽位坐标的具体数值（需读常量表）。
- 迷宫网格数据（`map_d`）与原版交互的映射：原版是否真的把整个迷宫渲染为"可走网格"？目前反汇编只看到 5 槽位 + 3 热区，**没有看到任意格行走逻辑** —— 需结合截图 `maze-007.png` 与 `0x20563C8` 逐帧确认。
- `0x2057210 / 0x20586C0 / 0x205CEA0`（r4==1/2/4 分支）的功能。
