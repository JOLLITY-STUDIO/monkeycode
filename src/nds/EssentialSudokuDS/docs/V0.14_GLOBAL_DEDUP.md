# V0.14 Global Dedup (ADR-014)

## 背景
V0.13 pattern detector 给 51 个函数自动命名 (`auto_<kind>_<fn_addr>`). 名字带函数自己的 addr 但没说
它操作哪个 global — 业务代码 import 时仍不知道这 setter 写哪个 state slot.

V0.14 用 `ldr rN, [pc, #N]` 模式的 pc-relative 加载提取 target global ptr:
- ARM 模式: PC = ldr_addr + 8, target = ldr_addr + 8 + N
- 从 binary (arm9.bin / arm7.bin) 读 target 处的 4-byte word

新命名: `auto_<kind>_<target_ptr_short>` (e.g. `auto_state_setter_02101be8`)
- 两个 setter 操作同一个 global 时名字相同 → 暴露真实 duplicate 函数
- 解决: 用 `_a` / `_b` / `_c` 后缀

## 设计
**脚本**: `scripts/pattern_detector.py` (扩展 V0.13)
**新函数**: `extract_pc_relative_target(lines, fn_addr, binary, load_addr)`
- 接受 raw disasm lines (含 addr+bytes prefix)
- 找第一条 `ldr rN, [pc, #N]` insn 的实际 addr
- 计算 target = ldr_addr + 8 + offset
- 从 binary 读 4 bytes little-endian → uint32 global ptr

**Naming**:
```
Before: auto_state_setter_02020f3c (uses function's own addr)
After:  auto_state_setter_02101be8 (uses target global ptr)
```

**Collision detection**:
- 2+ funcs 名字相同 → 真实 duplicate (or 1 function misdetected as 2)
- 加 `_a` / `_b` / `_c` 后缀 → names unique again

**Output**:
- `rom-data/v014-pattern-suggestions.json`:
  - `names[]` — 51 suggestions, 每条带 `target_global_ptr` field
  - `clusters[]` — (pattern_kind, target_global) 聚类 (25 唯一 + 6 collisions)
- `miniprogram/utils/nds/functions/arm9.ts` etc. — 新命名直接 export

## 12 个缺 target 的原因
- `tail_call` × 6 — destination is bx ip, pc-relative extract 没跟踪到 (不是 ldr 模式)
- `const_return` × 6 — 返回值是常量, target 即常量本身 (应该可以被提取但目前没实现)
