### 1.bis.4 F6-F2510 PPU 黑屏期（4167 帧 ≈ 70s）行为特点

1. **CPU 全速运行但屏幕黑** — bank02 audio 主例程每帧跑，A8EE 等 PPU buffer 在 RAM 中持续组装
2. **PPU bulk write 持续** — bank02 `$01:A039 STA $2007` 在 PPU off 状态下写 tile 数据到 RAM（实际 VRAM 不显示，但 ROM 持续写）
3. **OAM 持续 refetch** — bank02 `$01:A8EE STA $0202,Y` 把 sprite 数据写到 RAM `$0200-$02FF`，等 PPU enable 时一起呈现
4. **PRG bank switch 12+ 次** — bank00 动态切换模块，加载不同的代码片段
5. **完整开场动画的"画外音"在 RAM 中累加** — 等 PPU enable 那一刻画面 + 字幕同时呈现

### 1.bis.5 F6-F4355 综合 H5 翻译骨架

```typescript
class BootSequence {
  // F6: clear RAM
  clearRam() { for (a = $047B; a <= $05EF; a++) ram[a] = 0; }
  
  // F8: main loop entry, F2510 is end
  mainLoop() {
    while (!ppuEnabled) {
      // F30+: poll vsync flag
      while (ram.$1B & 0x80) {}
      
      // F32+: audio poll
      audio.poll();  // $A0ED (bank02)
      
      // F380: sprite OAM dump
      if (frameN % 70 === 0) sprite.dumpOam();  // $91A1
      
      // F1047+: PPU bulk write (subtitle/tile build up)
      if (frameN % 140 === 0) ppu.writeTile();  // $A039
      
      // F407/F461/F2416: PRG bank switch
      if (someCondition) moduleLoader.switch(id);
    }
    
    // F2510: PPU enable
    ppu.enable(0x89);  // $A17F STA $2000 = #$89
    
    // F2510+: visible animation
    showOpeningAnimation();
  }
}
```

### 1.bis.6 核心事实：boot 期间的"画面"

| "画面" 编号 | Frame | 内容 | 来源 bank |
|---|---|---|---|
| **画面 0** (黑屏 1) | F6-F12 | 完全黑屏 + 内存清零 | bank01 |
| **画面 1** (Capcom logo) | F13-F29 | Capcom logo（但 PPU off, 不可见） | bank00 `$9A7E` |
| **画面 2** (黑屏 2) | F30-F379 | 黑屏持续, vsync + audio 循环 | bank00+bank02+bank06 |
| **画面 3** (开场动画准备) | F380-F2509 | 第二画面 OAM dump + PRG switch + PPU bulk write（**PPU 仍 off**） | bank00+bank02 |
| **画面 4** (大空翼开场) | **F2510-F4355** | **可视画面**：PPU enable + sprite 持续更新 + 字幕推送 + audio 主循环 | bank02 主 + bank00 协 + bank12 audio |

### 1.bis.7 关键事实

**F2510 之前所有"画面"在 CPU 中准备，F2510 才一次性 PPU enable 一次性呈现。** 所以"boot 期间有 4 个画面"是误解 — 其实只有一个持续的画面在 F2510 才开始。

ROM 用了 4167 帧（70s）的 CPU 时间准备一个画面，然后一次性呈现 — 这是 90 年代 NES 游戏优化的典型手法。
