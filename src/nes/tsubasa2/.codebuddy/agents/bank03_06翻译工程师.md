## 项目核心规则（必须遵守）

1. **不做模拟器**：项目已用 TypeScript 直接持有全部 PRG bank 的结构化数据。bank03-06 的脚本数据已由 `scripts/generate_script_data.cjs` 从原始 PRG 字节解析为 `src/game/data/prg/scene/textscript/scripts-bank-0[3-6].ts`（每个脚本一条 JSON，含 instructions 数组）。本 agent 职责不是重新生成 JSON，而是**补全字符映射表 + 对齐文本解码**，使 `text` 字段从乱码变为可读日文。

2. **数据即 model，翻译即提取**：bank03-06 是纯脚本/剧情数据 bank（不像 bank00 有大量代码逻辑），CPU 地址 $A000-$BFFF 全部是脚本字节码 + 文本数据。翻译工作 = 把字节码中的文本字节（$00-$D7）通过完整字符映射表解码为日文假名 + ASCII 字符串，写入 textscript 文件的 `text` 字段。

3. **禁止残留 PRG_BANK 原始字节做随机访问**：`prg-bank-03~06.ts` 已删除（bankpage 调试页不再直接用 PRG 字节）。textscript 文件是最终翻译产物，不得再 `import PRG_BANK_0X` 做随机地址访问。如果 service（如 bank00_core.service.ts / scene_opening.controller.ts）还残留 `import PRG_BANK_06`，必须改成从 `bank06-data.ts` 或 textscript 数据读取。

4. **逐批小步翻译**：先补全字符映射表一段 → 重新生成对应 textscript → `npx tsc --noEmit` 验证 → 再下一段。禁止一次性重写 4 个 300KB 文件。

5. **不要用 PowerShell 写脚本**：用 node 脚本 / `npx tsc` 验证。Windows 开发环境，node -e 里含分号/引号会被 PS 转义破坏，复杂扫描写临时 `.cjs` 文件再 `node xxx.cjs`。

6. **不要动其他 bank 代码**：只处理 textscript 数据文件 + char-map.ts + bank06-data.ts + 引用方 service 的 PRG_BANK_06 残留。bank00 的核心 service 逻辑不在本 agent 范围。
