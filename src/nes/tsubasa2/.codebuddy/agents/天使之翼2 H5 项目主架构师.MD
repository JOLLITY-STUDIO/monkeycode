需要按照原来的模拟器+rom项目架构，重新设计H5 ts版本架构，并实现对应的功能，
要求翻译prg asm为为高级语言，去掉6502编码和cpu模拟器
又编程思想、设计模式、系统架构设计、面向对象经验，写法主偏向java开发语言（但是有asm\C\C++\VB\HTML\JS\java\python\TS\NODE等开发语言经验）。熟悉各种前后端框架设计。功能无依赖解耦。即插即用，即拔即走的模块化编程。熟悉底层性能优化。数据结构设计、还有各种算法。

## 架构现状分析（日期: 2026-08-21）

### 当前架构分层

项目采用 MVC 分层，但层间边界仍有交叉：

```
┌─ Control ─ Tsubasa2.ts (NES 主板纯入口) + DispatchService (真实 RESET 分发链)
│              构造函数注入所有 Bank Service，RAF 循环驱动每帧
│
├─ Service ─ src/game/service/bankN_*.service.ts (PRG bank 翻译)
│             每个 Bank = 一个 Service 类，消费 DataStore + 自有 data
│             bank00/ 子目录含 core + scene controllers + script-vm
│
├─ Model  ─ src/game/data/prg/DataStore.ts (KV 数据中心)
│             NT/OAM/Palette/ZP/RAM 一体化
│             data/prg/ 下有 bankXX-data.ts + prg-bank-XX.ts (ROM 原始字节)
│             data/chr/ 下有 chr-bank-00~15.ts (CHR 图形数据)
│             data/prg/audio/ 下有 BGM 44 首 + SE 16 个
│
├─ View  ─ src/game/view/ (SceneView 基类 + 各场景 View)
│           bank00/Bank00RenderView.ts (NT/调色板/OAM/PPU Buffer 渲染)
│           LevelUpView/MeetingView/OamView/PasswordView/SceneView/ShowcaseView
│
├─ Core  ─ src/core/ppu/ (tsnes PPU, 2248 行, @ts-nocheck)
│          src/core/papu/ (tsnes PAPU, 705 行, @ts-nocheck)
│          src/core/mappers/ (mapper0~241, 含 MMC3 mapper4)
│          src/core/debug/ (调试面板/NT viewer/Palette viewer 等)
│          src/core/types.ts (73 行, 仅基础常量/枚举/接口)
│
└─ Pages ─ pages/tsubasa2/ (微信小程序游戏页面)
           pages/bankpage/ (调试聚合页 + bank-detail 子页)
```

### 核心入口 (Tsubasa2.ts) 分析

- **职责**: NES 主板纯入口，构造函数注入 16 个 Bank Service + PPU + DataStore
- **RAF 循环**: `_onFrame` (逻辑) → `_onRender` (PPU 渲染) → `putImageData`
- **无头接口**: `prepare()` + `stepFrame()` 供无界面测试
- **问题**: PPU 以 `as any` 注入 stub nes 对象 (L125-137)，CHR Bank 注册仅 `console.log` (L412-413)

### DataStore 分析

- **结构**: NT0/NT1 (32×30 tile 网格) + OAM 精灵 + Palette + RAM KV + ZP
- **OAM 管理**: OamManager (影子缓冲 $04A5) + ShadowOam ($0468 影子精灵表)
- **VRAM 缓冲**: $04A5 线性 VRAM 写缓冲 → `commitVramToNT()` 提交到 NameTable
- **问题**: DataStore.ts 822 行，OamManager + ShadowOam 内联其中，职责过重

### 优先级 P0 (阻塞核心流程)

- [ ] **T1: PPU 渲染管线对接 — CHR Bank 注入 + DataStore→PPU 同步**
  - 位置: `src/game/Tsubasa2.ts` L407-413 (`_registerAllChrBanks` 空 console.log)、`src/core/ppu/index.ts`

    1. 在 Tsubasa2 构造时将 chr-bank-00~15.ts 数据写入 PPU 的 `vramMem` (pattern table 区域 $0000-$1FFF)
    2. 每帧 `_onRender` 中将 DataStore.nt0/nt1 + sprites + paletteTable 同步到 PPU 内部状态
    3. PPU `endFrame()` 读取 DataStore 数据渲染，而非依赖 NMI/CPU 写入

- [ ] **T5: 依赖注入容器 (DI/IoC) — 消除构造函数 16 个 new**
