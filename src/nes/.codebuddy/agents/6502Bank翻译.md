# 翻译流程 SOP

## 阶段 1：数据层 — `tsubasa2-h5-src/src/data/bank{N}-data.ts`
- 头部注释: 来源(rom-data/prg-bank-{N}.ts) / CPU 映射 / PRG offset
- `B{N}_CPU_BASE = 0x8000` + `B{N}_DATA`（原始字节，自动提取不做结构化，直接引用 rom-data 数组内容）
- 导出通用访问器 `readB{N}(addr)` / `readB{N}U16(addr)`（addr 支持 $8000-$9FFF 与 $A000-$BFFF 双窗口，$A000 窗口物理偏移 = addr-0xA000）
- 对反汇编中识别的每张指针表/查找表，导出表专用访问器（如 `readB27Decrement / readB27AnimScriptPtr / readB27ScenePtr`），带注释说明索引与表语义

## 阶段 2：服务层 — `tsubasa2-h5-src/src/game/bank{N}_*.service.ts`
- 头部注释: CPU 映射 / PRG offset / 全部 code 段清单（地址+字节数+入口名）/ 固定区辅助映射表（`$C50C→$CD7C 语义` 格式）
- `export class Bank{N}Service { constructor(private _store: DataStore) {} }`
- RAM 地址 → 语义化 KV 常量: `const KEY_XXXX = 'ram_XXXX'`（命名规则: ram_ + 大写 hex 4 位）
- 每个入口一个公开方法（如 `entry_8104(arg)`），逐条按汇编翻译：
  - JSR 到固定区 → 私有语义化辅助方法 `_fixedXXXX()`（H5 无硬件操作如渲染同步/缓冲切换 → 空实现并注释）
  - 处理器标志位（carry/zero）用显式布尔/位运算表达，逐行注释对应汇编地址（如 `// $8113-$8121: carry = (arg ≥ $0B)`）
  - 指针读写用 `_setPtr/_getPtr`，字节/16bit 用 `_read16`，零页用 `_readRamByte/_writeRamByte`（addr→key 转换）
- 纯函数（坐标换算/表查询）独立成 `_fixedXXXX` 便于差分验证
- 最终代码不得残留未识别二进制/十六进制硬编码，数据一律走数据层访问器

## 阶段 3：差分验证 — `tsubasa/src/tsnes/_verify_bank{N}.cjs`
- 编辑 `tsubasa2-h5-src/tsconfig.test.json` 的 include 加入新数据层+服务层文件 → `npx tsc -p tsconfig.test.json` 编译到 `_test_out/`
- 验证脚本 = 独立参考实现（纯 JS 按汇编逐条复刻，含 8bit 回绕/进位细节，不引用 service）+ 实际 service 对比：
  1. 随机对比: 固定种子 LCG（如 `rng*1103515245+12345`），每入口数千组随机输入（arg/相关 RAM 位随机）比对输出与副作用
  2. 确定性用例: 用真实 ROM 数据驱动（如真实脚本帧 → OAM 逐字节比对、真实场景字节 → 名字区输出），覆盖分支：arg≥$0B / carry 分支 / $FF 跳转 / flag=0 停止 / 帧延迟递减
  3. 纯函数全量/随机对比（256 组全量 + 数千随机）
- 末尾 `console.log(PASS=.. FAIL=..)` + `process.exit(fail?1:0)`，FAIL 时打印 `用例名 | 输入 | got | exp`
- 必须 PASS=全部/FAIL=0 才算通过；发现语义分歧回到阶段 2 修正再验
