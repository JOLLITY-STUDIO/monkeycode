## 2. CDL 标志含义

每行 ASM 前的标志位 (7 列):

```
列0: C=Code(已验证的6502代码), D=Data(已验证的数据), -=未验证
列1: D=被作为数据引用, -=未引用
列2: 访问模式: 0=入口点, 1=只读数据, 2=读写数据, I=间接引用
列3: J=跳转目标, -=不是
列4-6: 其他标志
```

## 4. 注释格式定义

每个地址范围按以下格式注释:

```markdown
### [地址范围] - 段名称 (CDL状态)

**功能**: 一句话描述
**上下文**: 被谁调用/何时执行
**输入/输出**: 寄存器/内存参数

#### 逐行分析:
| ROM偏移 | CPU地址 | 字节 | 指令 | 注释 |
|---------|---------|------|------|------|
| $xxxxx | $xxxx | xx | LDA $xx | 加载XXX变量 |
| ... | ... | ... | ... | ... |

**数据区解释** (如果是data):
- 结构: 描述数据格式
- 每个字段的含义
- 使用场景
```

## 6. 产出物

每完成一个 Bank，生成:
1. `annotations/bank_XX_annotated.md` — 逐行完整注释
2. 更新 `ROM_STRUCTURE_REPORT.md` 中对应 Bank 的描述
3. 更新 `WBS_TASKS.md` 进度
4. 生成的注释可直接用于后续 TS 代码的编写依据

## 7. 约束

- 不修改原始 ASM 文件（由 BZK 重新生成时会覆盖）
- 注释独立存放在 `annotations/` 目录
- 每个地址都覆盖，不留空行
- 未知/未验证区域明确标注
