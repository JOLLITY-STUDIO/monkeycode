## ⚠️ 重要：BUG-020 导致架构回退

**BUG-020** (2026-08-05 发现): `StateMachine.ts` 的 `STATE_DISPATCH_MAP` 与 ASM `$81FD` 跳转表严重不符。
**8个状态映射7个错误 + 1个多余 = 全部错误。**

整个 StateMachine 架构建立在错误假设上（假设所有状态在 Bank 1），这意味着：
- M2 (State 00-02) → 仅有 State 0 映射正确，State 1/2 实际在 Bank 5/6
- M3 (State 03-04) → State 3 实际在 Bank 5，State 4 是比赛主循环（非 Bank 4）
- M4 (State 05-07) → State 5 是状态转换器，State 6/7 在 Bank 6

**以下里程碑已被回退，需要基于 ASM 重新构建。**

## 当前执行任务 (2026-08-05)

### 🔴 最高优先级: M2-R.1 $81F7 状态调度器分析

**BUG-020 根因**: 之前没有从 ASM 的 $81F7 状态调度器开始分析，而是看到 Bank 1 有跳转表就假设所有状态在 Bank 1。

**当前任务**: 从 `bank_00_code.asm` 的以下关键地址开始，逐行分析：
- `$81F7-$81FC`: 状态调度器入口，从 `ram_03CB` 读取当前状态
- `$81FD-$820C`: **8 条目的跳转表** (每个 2 字节 = 目标地址低字节+高字节)
- `$820D-$8246`: State 5 处理器（状态转换管理器）
- `$8247-$8263`: 其他 state 的 $84D2 调用
- `$8264-$826F`: State 6 处理器
- `$8270-$8275`: State 7 处理器
- `$8276-$82A0`: State 2 处理器
- `$82A1-$82A6`: State 0 处理器
- `$82A7-$82AC`: State 1 处理器
- `$84D2-$8516`: **核心** - Bank 切换 + 子状态分发函数
- `$85CD-$87B8`: State 3 处理器
- `$87B9-...`: State 4 比赛主循环

**方法**: 
1. 确认跳转表 8 个条目分别跳到哪个地址
2. 分析每个地址的 $84D2 参数（如果有调用 $84D2）
3. 对于不调用 $84D2 的状态（State 4/5），分析其直接处理逻辑
4. 输出正确完整的 STATE_DISPATCH_MAP
