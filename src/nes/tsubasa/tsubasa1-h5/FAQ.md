# FAQ - 常见疑问与代码解读

## FAQ-001: 为什么不从ASM直接分析出代码？

**用户质疑 (2026-08-05)**: 现有TS代码的STATE_DISPATCH_MAP几乎全部错误——8个状态7个映射错误。
TS代码不是从ASM分析来的，而是猜测+编造的。

**回答**: 用户完全正确。以下是ASM vs TS的具体对比：

### 状态跳转表 ($81FD) ASM 实际 vs TS 实现

| State | ASM 跳转入口 | $84D2参数 | TS实现 | 正确? |
|-------|-------------|----------|--------|-------|
| 0 | $82A1: LDA #$10 | Bank 1, sub 0 | Bank 1, sub 0 | ✅ |
| 1 | $82A7: LDA #$5D | Bank 5, sub D (13) | Bank 1, sub 2 | ❌ |
| 2 | $8276: LDA #$60 | Bank 6, sub 0 | Bank 1, sub 5 | ❌ |
| 3 | $85CD→LDA #$5A | Bank 5, sub A (10) | Bank 1, sub 6 | ❌ |
| 4 | $87B9 (比赛主循环) | 无$84D2 | Bank 4, sub 0 | ❌ |
| 5 | $820D (状态转换管理) | 非简单dispatch | Bank 4, sub 1 | ❌ |
| 6 | $8264: LDA #$63 | Bank 6, sub 3 | Bank 4, sub 2 | ❌ |
| 7 | $8270: LDA #$61 | Bank 6, sub 1 | Bank 4, sub 3 | ❌ |
| 8 | 不存在 | N/A | Bank 1, sub 7 | ❌(多余) |

**根因**: 看到Bank 1有跳转表($804B)，就猜所有状态都在Bank 1。实际上每个Bank都有各自的跳转表。

### $84D2 分发器实际逻辑
```
PHA           ; 保存状态ID (如 $5D)
LSR x4        ; 提取高4位 → Bank编号 (5)
JSR $83C5     ; 写入PRG Bank寄存器
PLA           ; 恢复状态ID
AND #$0F      ; 提取低4位 → 子状态索引 (D=13)
ASL+ADC       ; ×3 (跳转表每项3字节)
JMP ($05FB)   ; 跳转到对应Bank的$C000+偏移处
```

## FAQ-002: Bank 1 的跳转表 $804B 用途

**位置**: bank_01_code.asm 第42-57行
**内容**: 3字节跳转表:
- [0] $C05B - 标题初始化1 (CHR bank设置)
- [1] $C070 - 标题初始化2 (加载图形→$C2C2 RLE解码器)
- [2] $C0A7 - 标题动画循环
- [3] $C0BE - 翻页过渡效果
- [4] $C0ED - 下一页/进菜单判断
- [5] $C106 - 菜单初始化
- [6] $C181 - 菜单循环
- [7] $C213 - 其他功能

**使用方式**: Bank 1内部通过`JSR $8017`间接跳转，用`ram_03CB`作索引。
Bank 1的$C015代码负责管理这些子状态的生命周期。

## FAQ-003: 为什么Bank 1最复杂？

Bank 1包含了:
1. 标题画面的5页分步加载（对应$03CB子状态0-4）
2. 菜单画面初始化（子状态5）
3. 菜单循环逻辑（子状态6）
4. RLE名称表解码器（$C2C2）
5. 调色板动画处理器（$C36C/$C383）
6. 精灵OAM解码器（$C259）
7. 数据指针查找（$C3BA）

Bank 1的RLE数据存储在Bank 2/5区域，通过跨Bank调用加载。

## FAQ-004: BUG-020 — 状态调度器完整分析 (2026-08-05)

### 用户反馈
"所以wbs 阶段只能回退到你出现这个bug的状态，之后的状态都是未完成。"

### 确认的 ASM 跳转表分析 ($81FD-$820C)

从 `bank_00_code.asm` 直接读取的跳转表（8条目×2字节 = 小端地址）:

| State | 跳转表字节 | 目标地址 | 目标代码 | $84D2参数 | Bank/Sub |
|-------|-----------|---------|---------|----------|----------|
| 0 | $A1 $82 | **$82A1** | LDA #$10, JSR $84D2 | $10 | Bank **1**, Sub **0** |
| 1 | $A7 $82 | **$82A7** | LDA #$5D, JSR $84D2 | $5D | Bank **5**, Sub **D** (13) |
| 2 | $76 $82 | **$8276** | LDA #$60, JSR $84D2 | $60 | Bank **6**, Sub **0** |
| 3 | $CD $85 | **$85CD** | (初始化后) LDA #$5A, JSR $84D2 | $5A | Bank **5**, Sub **A** (10) |
| 4 | $B9 $87 | **$87B9** | 比赛主循环 (LDA $0600...) | **无$84D2** | Bank 0 (不切换) |
| 5 | $0D $82 | **$820D** | 状态转换管理器 (LDA #$00...) | **无$84D2** | Bank 0 (不切换) |
| 6 | $64 $82 | **$8264** | LDA #$63, JSR $84D2 | $63 | Bank **6**, Sub **3** |
| 7 | $70 $82 | **$8270** | LDA #$61, JSR $84D2 | $61 | Bank **6**, Sub **1** |

### $84D2 函数确认 ($84D2-$84EC)

```
$84D2: PHA           ; 保存参数 (如 $5D)
$84D3: LSR x4        ; 高4位 → Bank编号 (5)
$84D7: JSR $83C5     ; 写入 $1C (PRG Bank寄存器)
$84DA: PLA           ; 恢复参数
$84DB: AND #$0F      ; 低4位 → 子状态索引 (D=13)
$84DD: STA $05FC     ; 存储子状态索引
$84E0: ASL           ; ×2
$84E1: ADC $05FC     ; +1 → ×3 (每个跳转表条目3字节)
$84E4: STA $05FB     ; 低字节偏移
$84E7: LDA #$C0      ; 跳转表基址高字节
$84E9: STA $05FC     ; 完整地址 = $C0xx
$84EC: JMP ($05FB)   ; 跳转到目标Bank的$C000+跳转表
```

**关键理解**: 每个PRG Bank在 `$C000` 处都有一个3字节跳转表，$84D2 切换到目标 Bank 后跳转到该 Bank 的对应子状态。

### State 4 (比赛主循环) 确认
- `$87B9` 直接读取 `ram_0600`（比赛状态变量），**不调用 $84D2**
- 这是一个在 Bank 0 内直接执行的主循环，通过 `ram_0600` 的位标志控制子流程
- 内容包括：球员移动、球物理、AI、碰撞检测等

### State 5 (状态转换管理器) 确认
- `$820D` 使用 `ram_03E3`/`ram_03E4`/`ram_03E5` 作为状态计数器和转换条件
- 通过 `INC/DEC ram_03CA` 修改主状态来推进游戏流程
- 例如：半场后递增到 State 6，终场后递增到 State 7

### 之前的 TS 错误映射回顾

| State | TS 错误映射 | 实际 ASM 映射 |
|-------|------------|--------------|
| 0 | Bank1/0 ✅ | Bank1/0 |
| 1 | Bank1/2 ❌ | **Bank5/D** |
| 2 | Bank1/5 ❌ | **Bank6/0** |
| 3 | Bank1/6 ❌ | **Bank5/A** |
| 4 | Bank4/0 ❌ | **Bank0 (直接)** |
| 5 | Bank4/1 ❌ | **Bank0 (直接)** |
| 6 | Bank4/2 ❌ | **Bank6/3** |
| 7 | Bank4/3 ❌ | **Bank6/1** |
| 8 | Bank1/7 ❌ | **不存在** |

### WBS 回退决定
因 BUG-020，以下里程碑已回退：
- **M2** (State 00-02) — State 1/2 分配错误
- **M3** (State 03-04) — State 3/4 分配全部错误
- **M4** (State 05-07) — State 5/6/7 分配全部错误
- **M4A** (ROM 数据提取) — 需在纠正状态机后进行

**不受影响的基础组件**: M1 (项目框架), RESET流程, NMI处理, PPU队列, 输入读取, RNG, CHR渲染管线

## FAQ-005: 音频为什么现在才加入？ (2026-08-05)

### 用户原话
"我说了还有音频呢"

### 回答
用户正确指出音频模块被遗漏。项目从一开始就没有规划音频，所有文档中搜索不到 audio/sound/music/APU 相关内容。

### ASM 音频引擎分析
Bank 1 `$9B00-$9FFF` 包含完整的 NES APU 5通道音频引擎：
- **入口**: `$9B00` SoundFrameUpdate (每帧调用)
- **4条音乐通道**: Pulse 1 (`$4000-$4003`), Pulse 2 (`$4004-$4007`), Triangle (`$4008-$400B`), Noise (`$400C-$400F`)
- **通道状态**: `$0759-$0798` (4通道 × 16字节)
- **操作码跳转表**: `$DC64` (8条目)
- **音乐指针表**: `$E1A8` (每个曲目 2字节)
- **音效触发**: `$07F9` 标志位 + `$9CEC` SoundInit

### 技术方案
- **APU 模拟**: `ApuSimulator` → Web Audio API (OscillatorNode + Noise buffer)
- **音乐引擎**: `AudioEngine` → 移植 ASM $9B00 播放逻辑
- **数据提取**: Python 脚本从 ROM 提取音乐序列数据 → 结构化 TS 数据
- **小程序兼容**: `wx.createWebAudioContext()` 或 `WebAudioContext`

### 新增文件
- `src/audio/ApuSimulator.ts` — APU 模拟器核心
- `src/audio/AudioEngine.ts` — 音乐/音效引擎
- `src/audio/MusicData.ts` — 音乐数据占位 (待ROM提取)
- `src/audio/index.ts` — 模块导出
- `scripts/extract_music_data.py` — ROM音乐数据提取工具

### 状态
已创建模块骨架，已加入 WBS (M_AUDIO 里程碑, 8任务, ~29h)。
音乐数据为占位，需要 ROM 提取后替换。

"问题是你进入state00-01就已经开始播放动画了背景音乐了呀，你不得一起做吗"

### 分析
用户完全正确。NES 原版游戏中，按下 POWER 键后：
1. **RESET → State 0 ($84D2($10) → Bank 1, Sub 0)**
2. Bank 1 的开场动画引擎立即启动：
   - **BGM 播放**：开场音乐由 Bank 1 音频引擎 ($9B00) 驱动，在 NMI 中每帧调用
   - **6 个分镜动画**：Bank 1 的 ram_03CB 从 0→1→2→...→7 逐步推进

     - Sub 1: 分镜1——标题 Logo 淡入 (CHR Bank 00+09, tile逐帧打印)
     - Sub 2: 分镜2——角色展示
     - Sub 3: 分镜3——转场过渡
     - Sub 4: 分镜4——角色特写 (CHR Bank 0D+0E)
     - Sub 5: 分镜5——大空翼立绘展示
     - Sub 6: 分镜6——动画收尾 (CHR Bank 0D+0F)
     - Sub 7: 过渡 → 标题画面 (切换 State 01)
   - **CHR Bank 切换**：每个分镜使用不同的 CHR Bank 组合（背景+精灵各一个）
   - **文字 Tile 逐字打印**：Bank 1 的 PPU 队列系统逐帧将文字 tile 写入 nametable

- 没有 CHR Bank 切换（从 1E/1F 到 00/09 到 0D/0E 到...）
- 没有文字 Tile 逐帧打印

### 修正计划

## FAQ-006: 微信小程序 WebAudio `GainNode.gain` 只读？ (2026-08-05)

### 用户错误日志
```
TypeError: Cannot set property gain of [object GainNode] which has only a getter
    at MpAudioParam.set (MpPlatform.ts:208)
```

### 回答
这是微信小程序 WebAudio API 的一个兼容性陷阱。

**标准 Web Audio API** 中，`GainNode.gain` 确实是只读属性（只返回 `AudioParam` 对象，不能被替换）。正确的做法是通过 `AudioParam.value` 来设置增益值：
```javascript
// ✅ 正确
gainNode.gain.value = 0.5;

// ❌ 错误 - 尝试覆盖 AudioParam 属性
gainNode.gain = 0.5;
```

**根因**: 我们的 `MpAudioParam` 包装器错误地尝试设置父节点的属性（`gainNode['gain'] = 0.5`），而不是操作 AudioParam 对象。

**修复**: 在构造函数中提取 `node.gain`（AudioParam 对象），然后对其 `.value` 进行设置。微信小程序和标准浏览器的 AudioParam 都支持 `.value` getter/setter。

**影响范围**: `MpGainNode` 和 `MpOscillatorNode` 都使用 `MpAudioParam`，一并修复。
