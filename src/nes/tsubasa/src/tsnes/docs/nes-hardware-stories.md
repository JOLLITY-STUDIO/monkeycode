# NES 硬件开发故事

> 记录搞这个项目时挖出来的 NES 硬件/软件细节。每条都可能帮你少踩一个坑。

---

## 1. 渲染不是即写即现：$05E8 队列 + VBlank 管道

**你的代码永远不直接写 PPU，而是塞进队列，等 NMI 来了再搬。**

```
游戏逻辑帧:  解析数据 → 写 $05E8 CPU 内存队列
     ↓
VBlank 中断:  NMI handler → 读 $05E8 → STA $2006/$2007
     ↓
下一帧扫描:   PPU 读 nametable → 画到电视
```

**原因**：PPU 只在 VBlank（或者渲染关闭时）接受写入。VBlank 极短（~2270 CPU 周期），一次只能写约 170 bytes。所以：
- 小更新 → 一帧完成
- 中等更新 → 分多帧
- 大更新（整屏切换）→ 关 PPU 渲染（`STA $2001, #$00`），写满，再开

## 2. PPU 先写高字节，CPU 先读低字节——两套芯片零协调

### CPU（Ricoh 2A03，基于 MOS 6502）
小端（little-endian），低字节在前。
**MOS Technology 1975 年定的**：加法器从低位算进位，低字节先来硬件最自然。

### PPU（Ricoh 自行设计）
`$2006`（PPUADDR）**先写高字节，再写低字节**。
`$2007`（PPUDATA）写一次地址自动 +1（或 +32）。

内部原理：PPU 里一个 toggle 触发器 + 两个 8 位锁存器：

```
第 1 次 STA $2006 → 锁存入 TMP_H
第 2 次 STA $2006 → 锁存入 TMP_L, 拼成完整 15 位地址
```

### 结果

ROM 里数据包存 `[lo] [hi]`（照顾 CPU 小端读），NMI handler 写 PPU 时从两个不同槽位分别取 hi 和 lo，手动调顺序：

```asm
; ROM 数据: [length] [addr_lo] [addr_hi] [tile...]
; 写 PPU:
STA $2006, addr_hi   ; 先高
STA $2006, addr_lo   ; 后低
; 再吐数据:
STA $2007 × N         ; N 个 tile
```

**两拨人没商量过字节序**。不是 bug，就是硬件史的一个注脚。

## 3. $2000 和 $2006 共享同一份地址

PPU 最终地址由 **三个来源拼成**：

```
PPUCTRL[$2000] bit1:0     → 地址 [11:10]  (nametable 选择: $2000/$2400/$2800/$2C00)
$2006 第一次写 bit7:0     → 地址 [13:8]   (高 6 位)
$2006 第二次写 bit7:0     → 地址 [7:0]    (低 8 位)

最终 = {PPUCTRL[1:0], $2006高[5:0], $2006低[7:0]}
```

所以操作顺序很重要：先设 `$2000` 选页，再两次 `$2006` 定偏移。

## 4. ROM 里的自定义"脚本协议"

NES 没有标准上传协议。游戏程序员在 ROM 里自创"微小脚本语言"，解析器是自己写的。

### 天使之翼的格式

```
【上传包】[长度(1B)][PPU地址lo(1B)][PPU地址hi(1B)][tile ID × N]
  0x00 = 包终止符

【控制码】0xE0-0xFF 范围
  0xE0 XX       — 设置状态/索引
  0xE1 XX       — 跳转/偏移
  0xE2 XX YY    — 设置二维参数
  0xE4 XX YY... — 输出字符串
  0xE5 XX       — 控制/routine 调用
  0xFC          — 字符串结束/换行
```

### 主循环就是一个分类器

```asm
LOOP:
    LDA ($88),Y        ; 读字节
    CMP #$E0           ; 控制码?
    BCS CONTROL        ; ≥ $E0 → 控制码处理
    JSR PARSE_PACKET   ; < $E0 → 上传包解析
    JMP LOOP
CONTROL:
    JSR CONTROL_HANDLER
    JMP LOOP
```

数据自带终止符（`0x00`），但主循环**永不退出**——停不停由控制码决定。

## 5. 数据表靠硬编码地址引用

游戏代码通过**绝对地址**（如 `$944E`）引用数据表，不是搜索或匹配。程序员写 ROM 时就约定好了"TECMO 的 tile 列表放在 bank 19 的 `$944E`"，就像你知道把某个文件放在桌面上。

MMC3 mapper 下，bank 19 映射在 CPU 地址 `$8000-$9FFF`，8KB。不同任务切换不同 bank 到同一窗口。

---

## 6. 小端存储在实践中的样子

十六进制 `$216E` 在内存里：

| 地址 | 值 | 含义 |
|------|-----|------|
| `$00` | `6E` | 低字节 |
| `$01` | `21` | 高字节 |

6502 的 `LDA (ptr),Y` 读出来第一个就是 `$6E`（低字节），零额外指令就能拿到低字节开始算——虽然 PPU 要求反过来写。



NES 本身输出的是 NTSC 信号，没有固定的 RGB 值，每个模拟器用的 palette 表都不太一样
